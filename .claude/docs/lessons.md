# QA Lessons

- **A checkpoint asserting "the modal closed" can be sampled too early.** Polling that breaks as soon as a success toast appears catches the toast while the modal is still mounted. Poll for *both* conditions, or re-sample a few seconds later, before recording the result. (AO-925, 2026-08-28)
- **Hand the wave's evidence tally to one `evidence-uploader` at wave close, then keep testing.** Do not dispatch an uploader per capture as each file lands on disk. (AO-925, 2026-08-30)
- **A dead upload worker can still be an alive process.** `status` reported `worker_pid: null` while the process ran on, so a second drainer started and the two raced the same job file. Check `pgrep -f "evidence_upload.py serve"`, not just `status`. (AO-925, 2026-09-03)
- **One upload *worker* live at a time — uploaders overlap, workers never do.** (AO-925, 2026-09-03)
- **`hideKeyboard` after a self-submitting input exits the app.** Maestro's `hideKeyboard` is a Back press on Android. A passcode/OTP screen that submits on its last digit has already dismissed the keyboard, so Back navigates out — from a root screen that means the launcher, and the flow reports `success`. Drop it after any self-submitting field and gate on the next screen instead. (AO-925, 2026-09-03)
- **`launchApp` needs an explicit readiness gate.** This RN app takes ~3 s to first render; `waitForAnimationToEnd` is not a barrier for it, so a conditional `runFlow: when: visible:` right after `launchApp` evaluates false and the block is skipped. Always `extendedWaitUntil` on something the target screen owns. (AO-925, 2026-09-03)
- **Maestro `takeScreenshot` appends `.png` itself.** Passing `…/name.png` writes `name.png.png`. Pass the path with no extension. (AO-925, 2026-09-03)
- **The first `inputText` after focusing an RN text field is silently swallowed.** A 6-digit OTP lands as 5 digits and the screen never self-submits; a long value lands truncated. Reproduced 4/4. Reliable pattern: type the value, `eraseText`, type it again — the second attempt lands in full. Always assert the field's value before moving on. (AO-925, 2026-09-03)
- **`eraseText` does not reliably clear a long or multiline RN field, and retyping over it duplicates characters.** Observed `Accountt`, `Accounthtt`, and a 40-char wallet address concatenated onto its predecessor. Wrap tap → `eraseText` → `inputText` → `assertVisible` in `retry`, and prefer a freshly-mounted (empty) field: a single `inputText` into an empty field is exact. (AO-925, 2026-09-03)
- **`swipe: direction: DOWN` can fire the system back gesture.** On this app it unmounted the form being filled instead of scrolling it. Use `scrollUntilVisible` with an element target; never a bare directional swipe to scroll a form. (AO-925, 2026-09-03)

- **Scope a date-picker's month-nav arrows to the header row.** Matching "buttons with no text" across the whole popover picks up unrelated controls; clicking the wrong one silently closes the picker, which reads as "navigation is broken". Find the header button (the one whose text matches `/\d{4}/`), then take its sibling buttons — first = previous, last = next. Backward nav can work while forward nav is broken, so verify both. (WT-14266, 2026-09-10)
- **Record toasts by marking the DOM node, not by de-duplicating text.** A `Set` of seen strings has to be cleared between steps, and clearing it re-registers any toast still on screen — so the previous step's error gets attributed to the current one. Stamp each toast element with a `data-seen` attribute instead, and read back only what appeared after a timestamp watermark. (WT-14266, 2026-09-10)
- **Never delete the toast container to "clear" toasts.** Removing the notification nodes takes the library's portal with them, and every later toast renders nowhere — turning real validation errors into apparent silence for the rest of the session. Wait for them to auto-dismiss instead. (WT-14266, 2026-09-10)
- **`setInputFiles` with the same path twice is a no-op.** The file input's value has not changed, so no `change` event fires and the app keeps the previous state — which reads as "the app ignored my upload". Call `setInputFiles([])` first, every time. (WT-14266, 2026-09-10)
- **Build size-boundary fixtures out of valid rows.** A 5 MB file padded with duplicate keys and a truncated final line is rejected by content validation before the size gate is ever reached, so the boundary goes untested and the result reads as a size failure. Pad a free-text column instead and keep every key unique. (WT-14266, 2026-09-10)
- **Inject driver helpers with `addInitScript`, not a bare `page.evaluate`.** Helpers defined by `evaluate` die on the next reload or re-login; registered as an init script they survive both, which matters on any surface whose session drops mid-run. (WT-14266, 2026-09-10)
- **A long admin run needs a re-login guard between waves.** This Root Admin SIT session dropped roughly every 15-20 minutes, sometimes mid-assertion, and the symptom is a helper throwing "field not found" rather than anything that looks like auth. Check for the login URL at the top of each batch. (WT-14266, 2026-09-10)
- **An upload that disables the query filters freezes them at whatever they held.** Set the account and date range *before* uploading; afterwards the controls are read-only and the stale values on screen are not what a later action necessarily sends. (WT-14266, 2026-09-10)
- **When a TC's expected result contradicts a business rule another TC verified, the TC is the bug.** Two cases here demanded Export Data be enabled on an uploaded working table while BR-9 requires it disabled — recorded as sheet corrections, not product defects, after checking which one the rule actually supports. (WT-14266, 2026-09-10)

## WT product lessons

- **Record the matrix point with every WT result.** env / client / server / account / platform, e.g. "transactCloud / mt5 / live / release_sit, Android". A finding without it cannot be verified by anyone else. (WT, ref-project)
- **Reproduce on the client the report concerns.** Features, symbols, and theme differ per client; a pass on lirunex settles nothing for centroid. (WT, ref-project)
- **Check the client and account gates before calling a feature missing.** Stop Limit, CRM, cross-server linking, Manage Funds, notifications are each legitimately absent for some client, server, or account type — see `.claude/domain/wt-shared.md`. (WT, ref-project)
- **A missing feature on the app is a build mismatch until the package check says otherwise.** `com.aquariux.wt.sit.lirunex` and `com.aquariux.wt.release.lirunex` are different installs; check `adb shell pm list packages` / `xcrun simctl listapps` first. (WT, ref-project)
- **Set the phone viewport (430×932) before the first navigation for mobile-web.** Same URL, different layout — the desktop render is a different UI. (WT, ref-project)
- **Replay the launch ritual on the app: skip ads, dismiss "Got it", relaunch.** Session and onboarding state persist between launches, so a fresh launch is not a fresh state. (WT, ref-project)
- **Record the observed live price and time.** Market data moves; without it a price-based expectation is unverifiable. (WT, ref-project)
- **Record device model and OS version.** Screen size changes layout and what is scrolled out of view. (WT, ref-project)
- **The same testid string carries across all four platforms, but the four trees diverge.** An Android answer does not settle a web question — confirm on the platform in question. (WT, ref-project)
- **Client-varying expected values come from the client-keyed table, never a hardcoded one.** Theme colours, server timezone, labels. (WT, ref-project)
- **Back Office and Root Admin writes leak into every test on that client.** Read the current value first; restore it, not a hardcoded default. (WT, ref-project)
- **Assert the requirement, not the current behaviour.** A wrong value the app shows today is a bug, not an oracle. (WT, ref-project)
- **Member-site market order is three clicks.** BUY sets direction → Place Order → Confirm. (WT, ref-project)
- **Jira only plays H.264 inline.** Convert `.mov` to `.mp4` before attaching. One bug = one verification comment. App bugs go under `WT`, never `QAT`. (WT, ref-project)
